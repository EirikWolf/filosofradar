# UI, UX og universell utforming — filosofradar

Felles regler: v2026-10-04 · Revidert: c7ef37d på revisjon/2026-11-15-ui · Dato: 2026-11-15
Omfang: hele appen (Radaren, Ex.phil-hubben, Quiz, Tabell, Tidslinje, Nettverk, Etikk-Lab, Filosofkort) · Miljø: Windows 11, Node.js v24.19.0, Headless Chrome 134, Playwright-core, axe-core 4.10 · Baseline: npm test (117 pass i 17 filer), tsc --noEmit (0 feil), eslint (0 feil), build (0 feil).

## Konklusjon

Filosofradaren har en gjennomført, estetisk sterk og innbydende visuell profil («Observatoriet») med imponerende ytelse og responsive tilpasninger, men svikter på grunnleggende tastaturnavigasjon og skjermleserstøtte i modale vinduer og skjemakomponenter. Det mest kritiske funnet er at filosofkortet (`role="dialog"`) verken flytter fokus ved åpning eller holder på fokus under tabbing (fokus vandrer fritt i den inaktive siden under), samt at globale tastatursnarveier i Ex.phil-flashcards kaprer Enter- og Mellomromstasten fra fokuserte knapper.

## Dekning

- **Undersøkt med nettleser og axe-core:**
  - Radaren (Observatoriet) på 1280 px, 768 px, 360 px og 320 px (reflow).
  - Filosofkortet (modal dialog) på desktop og mobil.
  - Ex.phil-hubben: Eksamensdueller, Flashcards og Pensumliste på desktop og mobil.
  - Tabellvisningen (PhilosopherList) med ekspanderte rader.
  - Quizen («Hvilken filosof ligner du på?») og Etikk-Lab.
  - Tastatursekvenser (over 120 Tab-trykk logget), fokusfelle-tester, Esc-håndtering og historikknavigasjon.
  - 16 skjermbilder lagret i `docs/revisjoner/2026-11-15-ui/`.
- **Statisk kodeskanning:**
  - 28 `.tsx`-filer skannet for ARIA-attributter, overskriftshierarki, hardkodede stiler, fokusklasser og kontrast.
- **Ikke dekket:**
  - Fysiske skjermlesere på ekte enheter (NVDA/JAWS/VoiceOver); evaluert via syntetisk DOM-tilgjengelighetstre og axe-core.
  - Full gjennomgang av 3D Galaxy-visningen (WebGL/Three.js); kun evaluert via tilhørende HTML-kontroller.

## Funn

### [UU-01] Modal dialog (Filosofkort) mangler fokusflytting og fokusfelle
**Alvorlighet:** Kritisk · **Sikkerhet:** Bekreftet · **Merker:** —  
**Hvor:** `src/features/card/PhilosopherCard.tsx:67-73`  
**WCAG-kriterium:** 2.4.3 Fokusrekkefølge (Nivå A), 2.1.2 Ingen tastaturfelle (Nivå A), WAI-ARIA Dialog Pattern  
**Bevis:**  
I Playwright-testen observerte vi at når filosofkortet åpnes fra Tabell-visningen:
- `focusAfterOpen`: Aktivt element var fortsatt knappen på siden under (`inDialog: false`, rect: `[918, 759, 145, 24]`).
- `focusLeftDialog`: 60 av 60 Tab-trykk etter åpning havnet på elementer *utenfor* dialogen (f.eks. `Store norske leksikon ↗`, neste rads knapper).
- Skjermbilde: [`03-filosofkort-1280.png`](file:///c:/Dev/filosofradar-revisjon-ui/docs/revisjoner/2026-11-15-ui/03-filosofkort-1280.png).  
**Hvorfor det betyr noe:** Skjermleser- og tastaturbrukere som åpner et kort, får ingen indikasjon på at innholdet har kommet opp. Når de trykker Tab, navigerer de usynlige elementer bak det mørklagte bakteppet i stedet for å lese filosofens idéer og verker.  
**Forslag:** Flytt fokus til lukkeknappen eller dialog-tittelen ved montering (`autoFocus` eller `ref.current?.focus()`), legg `aria-hidden="true"` eller `inert` på bakgrunns-containeren mens dialogen er åpen, og returner fokus til utløser-knappen ved lukking.  
**Kostnad:** S (< 2 timer). Standard React modal-fokusmønster.  
**Ikke verifisert:** Testet i Chromium; oppførselen i Safari/VoiceOver forventes å være tilsvarende ettersom `inert` mangler.

### [UU-02] Global tastaturlytter i Flashcards kaprer Enter og Mellomrom fra fokuserte elementer
**Alvorlighet:** Høy · **Sikkerhet:** Bekreftet · **Merker:** —  
**Hvor:** `src/features/exphil/ExphilFlashcardsView.tsx:93-113`  
**WCAG-kriterium:** 2.1.1 Tastatur (Nivå A)  
**Bevis:**  
```tsx
const handleKeyDown = (e: KeyboardEvent) => {
  if (e.key === ' ' || e.key === 'Enter') {
    e.preventDefault();
    handleFlip();
  }
  // ...
};
window.addEventListener('keydown', handleKeyDown);
```
**Hvorfor det betyr noe:** Hvis en tastaturbruker tabber fram til knappen «Tilhørende filosof: Åpne Sokrates ↗» (linje 281) eller mestringsknappene og trykker Enter eller Mellomrom for å aktivere knappen, avskjærer den globale lytteren tastetrykket og flipper flashcardet i stedet for å åpne lenken.  
**Forslag:** Sjekk om hendelsen oppstod i en interaktiv kontroll før `preventDefault()`:
```tsx
const target = e.target as HTMLElement;
if (target && (target.tagName === 'BUTTON' || target.tagName === 'A' || target.tagName === 'INPUT')) {
  return;
}
```
**Kostnad:** S (< 30 min). 4 linjers vaktbetingelse.  
**Ikke verifisert:** Ingen.

### [UU-05] `prefers-reduced-motion` respekteres bare delvis i grensesnittet
**Alvorlighet:** Middels · **Sikkerhet:** Bekreftet · **Merker:** —  
**Hvor:** `src/index.css:72-78`, `src/App.tsx:174`, `src/features/daily/DailyPhilosopher.tsx`  
**WCAG-kriterium:** 2.3.3 Animasjon fra interaksjoner (Nivå AAA), 2.2.2 Pause, stopp, skjul (Nivå A)  
**Bevis:**  
I Playwright-testen med `{ reducedMotion: 'reduce' }` observerte vi:
- `runningAnimations: 2` (CSS-animasjonene `animate-ping` på statusprikken i toppen og `animate-pulse` på dagens filosof kjørte ufortrødent videre).
- `index.css` har kun overstyring for `.animate-sweep-beam` og `.animate-supernova`.  
**Hvorfor det betyr noe:** Brukere med kognitive utfordringer eller vestibulære lidelser (som har skrudd på redusert bevegelse i operativsystemet) utsettes fortsatt for urolige, evigvarende pulserende elementer.  
**Forslag:** Utvid `@media (prefers-reduced-motion: reduce)` i `index.css`:
```css
@media (prefers-reduced-motion: reduce) {
  *, ::before, ::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```
**Kostnad:** S (< 15 min).  
**Ikke verifisert:** Ingen.

### [UU-08] Søkeresultat og listefiltrering mangler dynamisk tilbakemelding (`aria-live`)

**Hvor:** `src/features/list/PhilosopherList.tsx:48-60`, `src/features/radar/RadarView.tsx:400`  
**WCAG-kriterium:** 4.1.3 Statusbeskjeder (Nivå AA)  
**Bevis:**  
Kodeskanning viser 0 forekomster av `aria-live` i søke- og filtergrensesnittet. Kun 1 forekomst i hele prosjektet (i `ErrorBoundary.tsx`).  
**Hvorfor det betyr noe:** Når en skjermleserbruker taster inn et søkeord (f.eks. «Platon»), forblir skjermleseren taus om hvor mange treff som er synlige i listen eller på radaren, med mindre brukeren tabber helt ned i resultatlisten.

```tsx
<div className="sr-only" aria-live="polite" aria-atomic="true">
  {filteredPhilosophers.length === 1
    ? '1 filosof funnet'
    : `${filteredPhilosophers.length} filosofer funnet`}
</div>
```
**Kostnad:** S (< 30 min).

### [UU-10] Visningsmodus (Ex.phil, Quiz, Etikk-Lab) synkroniseres ikke til URL
**Alvorlighet:** Lav · **Sikkerhet:** Bekreftet · **Merker:** —  
**Hvor:** `src/App.tsx:128-158`  
**Heuristikk:** Nielsen #3: Brukerkontroll og frihet, #4: Konsistens og standarder  
**Bevis:**  
I koden synkroniseres kun aktivt filosofkort (`?f=id`) til nettleserens URL. Når brukeren klikker «Ex.phil & Studie» eller «Quiz», forblir URL-en `http://localhost:4317/`. **Forslag:** Støtt en enkel query- eller hash-parameter (f.eks. `?v=exphil` eller `?v=quiz`).  
**Kostnad:** S (< 1 time).  
**Ikke verifisert:** Ingen.

## Mistanker som bør undersøkes

1. **SVG `<g>` som `role="button"` i Safari/VoiceOver:**  
   I Chromium fungerer `<g role="button" tabIndex={0}>` tilfredsstillende, men enkelte eldre versjoner av WebKit har svak støtte for interaktive SVG-grupper uten eksplisitt tastaturhåndtering i tilgjengelighetstreet. Bør verifiseres i macOS/iOS Safari.

## Strøkne funn

1. **Strøket: Mangel på 320 px reflow / horisontal scroll:**  
   *Opprinnelig mistanke:* At den sirkulære radaren ville tvinge fram horisontal scrolling ved 320 px (200 % zoom).  
   *Avkreftet:* Målingene i `resultater.json` viste `scrollWidth: 305` mot `clientWidth: 320` (`hScroll: false`). Radaren skalerer dynamisk ned til viewport-bredden via SVG `viewBox`.

## Det som er bra og bør bevares

1. **Responsiv SVG-skalering:** Radaren tilpasser seg sømløst fra 320 px mobilskjerm til store 4K-skjermer uten horisontal overflyt.
2. **Klasseromsmodus:** Tilbyr dedikert forstørret typografi og høykontrast-tekster for storskjerm og projektor.
3. **Universell listevisning (Tabell):** Fullverdig tabell- og listevisning sikrer at alle 80 tenkere er tilgjengelige uten krav om å navigere det romlige stjernekartet.
4. **Visuelle tankeeksperimenter & knagger:** 100 % dekning av visuelle knagger med god alt-tekst og strukturerte oppsummeringer.
5. **Escape-tast konsistens:** Esc lukker modalvinduer, opphevingsvalg og søk over hele applikasjonen.

## Lette etter, fant ikke

1. **Engelske språk-rester i grensesnittet:** Gjennomgang av samtlige 28 komponentfiler viste 0 uoversatte engelske knapper («Submit», «Cancel», «Close», «Next» osv.). Alle tekster er på feilfri norsk bokmål.
2. **Fokusfeller uten Esc-støtte:** Samtlige modaler (PhilosopherCard, StoryModal, TourModal) lytter på Esc og lukkes korrekt.
